# 배송 권역 관리 — 사용 설명서 (초안)

관리자 → 주문 · 배송 → **배송 권역** 메뉴. 우리가 배송하는 지역을 표로 관리하고,
권역 밖 고객이 남긴 "오픈 알림 신청"으로 다음에 열 지역을 정하는 화면입니다.

이 문서는 화면을 쓰는 사람을 위한 안내입니다. 개발 구조·롤백은 [DELIVERY_ZONE.md](DELIVERY_ZONE.md)를 보세요.

---

## 한눈에 보기

| 상황 | 어디서 | 무엇을 |
|---|---|---|
| 처음 세팅 | 권역 목록 → CSV 업로드 | 대구 9개 구·군 등록 (아래 CSV) |
| 어떤 단지가 출입 불가 | 예외 규칙 → 차단 | 단지명(또는 우편번호) + 사유 |
| 경계 밖 단지를 예외로 받기 | 예외 규칙 → 허용 | 우편번호 또는 단지명 |
| 폭설·기사 결근으로 하루 특정 구를 못 감 | 날짜별 중지 | 날짜 + 권역 + 사유 → 구독분 크레딧 |
| 어느 동네를 다음에 열지 | 대기 신청 | 지역별 신청 수 보고 결정 → CSV로 안내 |
| 권역을 껐더니 구독자가 있다 | 결제 보류 구독자 | 목록 보고 고객에게 연락 |
| 권역 밖 고객 결제를 막고 싶다 | 설정 → 배송 권역 → 판정 모드 | LEGACY → ZONES |

---

## 0. 두 가지 모드 (설정 → 배송 권역 → 판정 모드)

| 모드 | 권역 밖 주소가 주문하면 | 언제 쓰나 |
|---|---|---|
| **LEGACY** (기본) | 결제는 받고 "배송지 확인" 큐에 보류. 담당자가 전화로 안내 | 권역 표를 채우고 검증하는 동안 |
| **ZONES** | 결제 차단. 화면에 "우리 동네 오픈 알림 신청" 폼이 뜸 | 권역 표가 준비된 뒤 |

- 배포 직후에는 LEGACY 라 지금과 똑같이 동작합니다. 아래 1단계까지 마친 뒤 ZONES 로 바꾸세요.
- 예외 규칙의 **차단**은 모드와 상관없이 항상 결제를 막습니다.
- 언제든 LEGACY 로 되돌릴 수 있습니다. 권역 데이터는 그대로 남습니다.

## 1. 처음 세팅 — 권역 목록

### 1-1. 대구 9개 구·군 등록

권역 목록 탭 → "CSV 업로드" → `packages/db/prisma/seeds/delivery-zones.csv` 선택.
파일 내용은 아래와 같습니다. 법정동 코드 앞 5자리 = 구·군 전체입니다.

```csv
kind,code,name,sido,sigungu,isActive,memo
BCODE,27110,중구 전체,대구,중구,1,
BCODE,27140,동구 전체,대구,동구,1,
BCODE,27170,서구 전체,대구,서구,1,
BCODE,27200,남구 전체,대구,남구,1,
BCODE,27230,북구 전체,대구,북구,1,
BCODE,27260,수성구 전체,대구,수성구,1,
BCODE,27290,달서구 전체,대구,달서구,1,
BCODE,27710,달성군 전체,대구,달성군,1,외곽 면 단위는 운영하며 조정
BCODE,27720,군위군 전체,대구,군위군,0,2023년 편입 — 우선 비활성
```

이렇게 넣으면 지금의 "대구 전역"과 같은 판정이 됩니다. 군위군만 비활성으로 두어 그쪽 신청이 대기 목록에 쌓이게 했습니다. 실제로 가는지에 따라 바꾸세요.

> 코드는 행정표준코드 법정동 코드표 기준입니다. 업로드 전에 한 번 대조해 주세요.

### 1-2. 기존 고객 주소 반영

설정 → 배송 권역 → **"기존 배송지 좌표 보정·재판정"** 버튼을 한 번 누릅니다.
기존 배송지에 법정동 코드를 채우고 권역과 연결합니다. 끝나면 권역 목록의 "배송지 수"가 채워집니다.

### 1-3. 확인

- 권역 목록에서 각 구의 배송지 수가 그럴듯한지 봅니다 (달서구가 가장 많을 것).
- 메인 페이지 하단 "우리 동네 배송 가능한지 확인해 보세요"에 대구 주소와 경산 주소를 넣어 봅니다.
- 이상 없으면 설정에서 판정 모드를 **ZONES** 로 바꿉니다.

### 권역 목록 화면에서 할 수 있는 것

| 동작 | 설명 |
|---|---|
| 검색 | 이름·코드·구로 찾기 |
| 활성/비활성 토글 | 끄면 그 권역이 배송 불가가 됩니다. 끄기 전에 "활성 구독 N건" 확인 창이 뜹니다 |
| 단건 추가 | 종류(우편번호/법정동)·코드·이름 입력 |
| CSV 업로드 | 같은 코드는 덮어쓰고, 없는 코드는 추가. 표에 있는 걸 지우지는 않음 |
| CSV 양식 다운로드 | 빈 양식 + 예시 2행 |
| 삭제 | 연결된 배송지는 권역 연결만 풀림 |

**코드 자릿수 규칙**: 5자리 = 구·군 전체, 8자리 = 읍·면·동, 10자리 = 리. 여러 개가 겹치면 긴 코드가 이깁니다.
우편번호(5자리)도 되지만 한 동에 우편번호가 여러 개라 관리가 번거롭습니다. 미세 조정에만 쓰세요.

## 2. 예외 규칙 — 권역보다 우선

권역은 "이 동네 전체"이고, 예외 규칙은 "그 안의 특정 단지·우편번호만 다르게"입니다.

| 동작 | 예 | 결과 |
|---|---|---|
| **차단** | 성서주공1단지 — "공동현관 출입 불가" | 권역 안이라도 그 단지는 결제 불가. 사유는 고객에게 보임 |
| **허용** | 우편번호 38500 — "경산 경계, 기사 동선상 가능" | 권역 밖이라도 결제 가능 |

대상은 셋 중 하나만 고릅니다.

- **우편번호** — 정확 일치
- **단지명** — 띄어쓰기·대소문자 무시. 다른 구에 같은 이름이 있으면 시군구를 같이 넣기
- **사전 등록 단지** — 아파트 단지 메뉴에 등록된 단지를 고르면 표기 흔들림 걱정이 없음

규칙은 끄고 켤 수 있습니다. 공사가 끝나면 삭제하지 말고 비활성으로 두면 이력이 남습니다.

## 3. 날짜별 중지 — 돌발 상황

"그날은 배송일인데 이 지역만 못 간다"에 씁니다. 하루 전체를 쉬는 날은 **배송 캘린더**에서 끄세요.

### 등록

날짜 · 권역(또는 "전체 권역") · 사유 입력 → 등록.
사유는 고객 화면에 "…사정(폭설)으로 중지되었습니다"로 나가니 짧고 담담하게.

등록하면 바로:

- 그 날짜에 새 주문이 막힙니다 (다른 날짜는 그대로).
- 이미 잡힌 배송 건은 보류로 빠져 코스·피킹·기사 출력에서 제외됩니다.
- 화면에 영향 요약이 뜹니다: 단건 주문 N건 · 구독 배송 M건.

### 이미 결제된 건 처리

| 종류 | 방법 |
|---|---|
| 구독 배송분 | 표의 **"구독분 크레딧 적립"** 버튼. 그 날짜 금액이 크레딧으로 쌓여 다음 결제에서 빠집니다 (건너뛰기와 같은 정산) |
| "이번 주기만" 구독 | 크레딧을 쓸 다음 결제가 없어 버튼이 처리하지 않음. 건수만 보여주니 환불 신청으로 처리 |
| 단건 주문 | 주문 관리 → "배송지 확인" 필터에 같은 사유로 올라옴. 취소·환불하거나 배송일을 옮김 |

### 해제

날씨가 풀리면 **"해제"**. 이 중지 때문에 보류된 건만 다시 정상으로 돌아옵니다.
크레딧을 이미 적립한 구독분은 되돌아오지 않습니다 (고객이 다시 고르면 됩니다).

## 4. 대기 신청 — 다음에 열 지역 정하기

권역 밖 고객이 "우리 동네 오픈 알림 신청"에 남긴 이름·연락처·동네가 모입니다.

### 보는 법

- 위쪽 **지역별 집계**: 구·동별 신청 수, 마케팅 동의 수, 최근 신청일. 신청 많은 순.
- 행을 누르면 아래 목록이 그 동네로 걸러집니다.
- 기준을 하나 정해 두세요. 예: "한 동에 30건 넘으면 검토".

### 열기로 했을 때

1. 권역 목록에 그 동의 코드를 추가하거나(8자리), 비활성이던 권역을 켭니다.
2. 대기 신청에서 그 동네로 거른 뒤 **CSV 다운로드** → 문자 발송 (마케팅 동의 여부가 열에 있습니다. 동의한 사람에게만).
3. 보낸 사람을 체크하고 **"선택 안내 완료 표시"**. 두 번 보내지 않게 합니다.

### 개인정보

신청 폼에 "1년 보관 후 삭제"라고 약속돼 있습니다. 분기에 한 번 **"N일 이전 신청 삭제"**(기본 365일)를 눌러 주세요.

## 5. 결제 보류 구독자 — 권역을 줄였을 때

권역을 끄거나 단지를 차단하면 그 안의 구독은 다음 자동결제가 **조용히 멈춥니다**. 고객에게 자동 안내가 나가지 않습니다.

- 권역을 끈 날 이 탭을 열어 목록을 확인하고 고객에게 직접 연락하세요.
- 설정의 **"관리자 알림 휴대폰"** 에 번호를 넣으면 보류가 생길 때 문자로도 옵니다.
- 권역을 다시 켜면 다음 아침 크론에서 자동으로 청구됩니다. **"다시 판정"** 을 누르면 목록이 바로 정리됩니다.
- **"활성 구독 전체 점검"** 은 권역을 여러 개 바꾼 뒤 한 번에 훑을 때 씁니다.

## 6. 운영 리듬 (제안)

| 주기 | 할 일 |
|---|---|
| 매일 아침 | 결제 보류 구독자 탭에 새 건이 있으면 연락 |
| 주 1회 | 대기 신청 지역별 집계 확인 → 확장 후보 메모 |
| 권역 바꾼 날 | 끄기 전 확인 창의 구독 수 확인 → 끈 뒤 보류 구독자 연락 |
| 폭설·결근 | 날짜별 중지 등록 → 구독분 크레딧 → 단건 처리 → 풀리면 해제 |
| 분기 1회 | 대기 신청 1년 이전 건 삭제 |

## 자주 묻는 것

**Q. 권역을 끄면 기존 고객 주문이 취소되나요?**
아니요. 이미 결제된 주문은 그대로 갑니다. 새 주문과 다음 자동결제만 막힙니다.

**Q. 우편번호와 법정동 코드를 섞어 써도 되나요?**
됩니다. 둘 다 활성이면 어느 쪽이든 맞으면 가능입니다. 기본은 법정동 코드로, 우편번호는 예외적으로.

**Q. 고객이 "배송 가능"이라고 봤는데 결제에서 막혔어요.**
그 사이에 권역이 꺼졌거나 차단 규칙이 생긴 경우입니다. 결제 직전에 항상 다시 판정합니다.

**Q. 대구 밖인데 꼭 받아 주고 싶은 고객이 있어요.**
예외 규칙 → 허용에 그 우편번호를 넣으세요. 권역을 통째로 열 필요 없습니다.

**Q. ZONES 로 바꿨는데 문제가 생기면?**
설정에서 LEGACY 로 되돌리면 즉시 이전 동작(보류 접수)으로 돌아갑니다. 데이터는 남습니다.
